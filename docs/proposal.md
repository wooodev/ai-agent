# 따릉이 물어보기 기획서

## 1. 문제

동네 소식을 쓰는 지역 기자가 "우리 동네 따릉이는 언제, 어디로 많이 가나"를
확인하려면 대여소 간 이용 기록 CSV를 직접 집계해야 한다. 5일치만 합쳐도
126만 행이라 엑셀 행 한도(1,048,576행)를 넘어 한 번에 열리지 않는다.
출발·도착 이중 기록을 모르고 합치면 건수를 2배로 잘못 센다.
지금은 날짜별 파일을 하나씩 열어 필터와 피벗으로 센 뒤 손으로 더한다.

- 쓰는 사람: 지역 기자, 구청 자전거 정책 담당자 (SQL과 pandas를 모름)
- 지금 방법 (기준선): 엑셀 필터·피벗. 제품 안에서는 자주 묻는 질문 템플릿 SQL
- 트랙: A

## 2. 데모 시나리오 (3분)

1. 사용자가 "평일 아침 8시대에 따릉이 출발이 가장 많은 동네 3곳은?"을 입력한다
2. 화면에 답, 해석 한 줄("평일 = 10/22·23·26, 08:00\~08:59 출발"), 실행한 SQL, 결과표가 뜬다
3. 사용자가 "아침"을 7\~9시로 넓히도록 해석을 고쳐 다시 실행한다. 고친 기록이 남는다
4. "마포구 이용 건수는?"을 묻자 "구 정보가 없어 답할 수 없음"과 이유가 뜬다
5. 화면 아래에 "정답 10건 중 AI N건, 템플릿 M건 일치"가 뜬다

## 3. 범위

| 반드시                           | 이번엔 안 함 (이유)                                                        |
| -------------------------------- | -------------------------------------------------------------------------- |
| 질문 → SQL → 실행 → 답과 근거    | 구(區) 단위 질문. 행정동→구 대응표가 또 필요하고 동명 중복 함정이 생긴다   |
| 해석 한 줄 표시와 수정 후 재실행 | 개별 대여소 실제 이름 질문. ST- ID와 대여소 번호를 잇는 다리 데이터가 없다 |
| 읽기 전용 게이트                 | 대화 이어가기(멀티턴). AI 자리가 복잡해진다                                |
| "답할 수 없음" 처리              | 차트 자동 생성. 화면이 둘이 된다                                           |
| 정답 10건 일치율 표시            | 장기간 데이터, 실시간 API. 용량과 인증키 문제가 붙는다                     |

## 4. AI 자리 (하나)

- 입력: 한국어 질문 한 줄 + 테이블 스키마와 데이터 기간(코드가 넣는다)
- 출력: QueryPlan = sql + interpretation(한 줄) + answerable(bool) + reason
- 틀리면: 사용자가 해석과 SQL을 보고 고쳐 다시 실행한다. 실행은 항상 게이트를 지난다
- 없으면 (각본 대역 겸 기준선): 키워드로 템플릿 SQL 10개 중 하나를 고른다. 못 고르면 "답할 수 없음"
- 시그니처: `def to_query(question: str, schema: Schema) -> QueryPlan`
- 사다리 목표 칸과 근거: 2칸 (structured output) + 게이트. 모델이 따로 찾아올 정보가 없고 스키마는 코드가 넣어 준다. SQL 에러를 돌려줘 재시도하는 루프는 12주차 평가에서 실패가 많을 때만 검토한다

## 6. 스택

- 실행: docker compose (서비스 둘: app, db)
- 모델: LiteLLM, 기본 모델은 각 계열의 가장 싼 모델
- 출력: Pydantic + instructor, 스키마 하나 (QueryPlan)
- 저장: PostgreSQL. 63만 행이라 6장 2절의 "수십만 건이면 PostgreSQL" 조건에 해당한다. 앱은 SELECT만 되는 reader 계정으로 연결한다
- API: FastAPI 엔드포인트 하나 (/ask)
- 화면: 정적 HTML 한 장
- 하네스: 질문 하나당 모델 호출 1회 + budget guard + 질의 게이트(SELECT 하나, trips만, LIMIT)
- 테스트·CI: pytest + GitHub Actions
- 새 기술: 없음 (데이터 분석 트랙의 DuckDB 대신 배운 PostgreSQL과 pandas 사용)
- 배포 대상: Render 후보 (Docker + PostgreSQL). 무료 조건은 계정을 만들 때 확인하고 날짜를 적는다
