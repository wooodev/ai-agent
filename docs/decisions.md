# 결정 기록

## D-001 일별 대여 건수 데이터는 쓰지 않는다 (2026-11-01)

- 받아 본 것: 2024-01 \~ 2026-06 일별 대여 건수 (컬럼 두 개, 912일, 빠진 날 없음)
- 판단: 질문이 기간 합계·최대·최소 정도라 고정 템플릿으로 충분하다. 자연어 질의가 필요한 이유가 약하다
- 기간도 본 데이터(2026-10)와 겹치지 않는다

## D-002 본 데이터는 대여소 간 이용 통계 5일치 (2026-11-01)

- 시간대·요일·동네·출발→도착 조건이 섞인 질문이 가능하다
- 기간은 2026-10-22 \~ 10-26으로 고정한다. 장기간은 이번엔 안 함

## D-003 출발 기준 행만 쓴다 (2026-11-01)

- 같은 이용이 출발시간·도착시간 기준으로 두 번 들어 있다
- 이 함정은 모델이 아니라 전처리 코드가 없앤다. 모델은 질문 해석에만 집중한다

## D-004 대여소 현황 파일은 이번에 쓰지 않는다 (2026-11-01)

- 받아 본 것: 대여소 현황 2024.6 \~ 2026.6 (번호, 이름, 자치구, 주소, 좌표)
- OD 데이터의 ST-xxxx 숫자와 대여소 번호는 다른 체계다. 숫자만 맞춰 붙이면 약 2,740개 중 1,425개가 엉뚱한 대여소로 붙는다 (예: ST-1006 목5동 → 1006 강동구)
- 둘을 잇는 실시간 대여정보 API 1회 호출은 지금은 하지 않는다
- 그래서 개별 대여소 이름 질문은 이번엔 안 함. 질문 단위는 행정동

## D-005 서울 주요 121장소 영역은 확장 후보로 둔다 (2026-11-01)

- 받아 본 것: 실시간 도시데이터 매뉴얼, 121곳 목록, 영역 shapefile
- OD 데이터에 좌표가 없어 이을 수 없고, 이으려면 지리 연산이라는 새 기술이 하나 더 든다
- 실시간 API는 답이 5분마다 바뀌어 정답을 고정할 수 없다

## D-006 구(區) 단위 질문은 이번엔 안 함 (2026-11-01)

- 행정동→자치구 대응표가 추가로 필요하고, 비슷한 이름의 동(신사동/신사1동/신사2동)이 함정이 된다

## D-007 이용 시간·거리 질문은 보류 (2026-11-01)

- 전체*이용*분이 건수만큼의 합계인지 평균인지 데이터 정의서로 확인하기 전까지 정답을 확정할 수 없다

## D-008 저장은 PostgreSQL, 새 기술은 없음 (2026-11-01)

- 출발 기준 63만 행이라 "수십만 건이면 PostgreSQL" 조건에 해당한다
- 질의 생성이 있으므로 week09의 reader 계정 이중 게이트를 그대로 쓴다
- DuckDB는 새 기술 자리를 쓰므로 들이지 않는다
